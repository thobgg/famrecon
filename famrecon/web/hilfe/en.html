Help

This help describes every page of the interface, explains how famrecon computes its results, and answers frequent questions. The ? Help button at the top right of every page leads to the matching section.

What famrecon does

famrecon builds families from baptism, marriage and burial registers in table form and writes them as a GEDCOM file. The input is a table as local family book authors keep it: one row per parish register entry, columns in the author's own layout. The output is read by every genealogy program (Gramps, Ahnenblatt, webtrees, online family books).

In between lies family reconstitution: the program recognises which mentions in different entries refer to the same person (the child baptised in 1770, the groom of 1795, the deceased of 1831) and forms persons and families from them. What is clearly documented it links itself; close calls go to the review list. Nothing is discarded: every table row ends up in the GEDCOM, and a check verifies that.

The path in five steps: load tables → review the mapping → build → review list → GEDCOM.

What famrecon does not do: it does not read scans or handwriting, it does not add data from the internet, and it never changes your tables. Everything runs on your computer; no data leaves it (see Data and safety).

Start page and projects

A project is one place or one set of registers. Technically it is a folder inside the data folder (the path is shown at the bottom of the start page). It holds your uploaded tables, the mapping (zuordnung.toml), the project file (projekt.db) and the finished GEDCOM (projekt.ged).

Creating a project

Name
Letters, digits, hyphen and underscore, no spaces. The name becomes the folder name and the GEDCOM file name, for example millbrook.
Tables
One Excel workbook (.xlsx, .xlsm) with one sheet per register, or several files, or CSV/TSV files. You can select several at once. For CSV the delimiter (semicolon, comma, tab, pipe) and the encoding (UTF-8, Windows-1252, Latin-1) are detected.

After creating the project you land on the mapping. A project without tables can be created and filled later from the project page.

Example project

The button Create example project builds a complete project from a fictional family tree with 492 persons over seven generations. It is a good way to get to know the pages before loading your own data. It can be deleted at any time.

Which tables work

  • The first row holds the headers; from the second row on, each row is one entry.
  • One sheet or file per register (baptisms, marriages, burials). Sheet names such as "Baptisms", "Marriages", "Burials" help recognition but are not required: the register can be switched on the mapping page.
  • Dates as text (1778-08-31, 31.08.1778, 1778, also 1699-08-00 for "month known, day not") or as Excel dates.
  • Persons either in one cell ("Haag, Nicolaus, weyl., former coachman") or split into surname, given name, occupation. Both are fine; the normal form brings them together.
  • Placeholders for "not given" such as n/a, — or ? do no harm; the mapping recognises them as empty words.
  • Formulas are read as their last calculated value. Merged cells, images and formatting play no role.

Mapping: assigning columns to fields

Every author keeps tables differently. That is why famrecon has a fixed field catalogue inside and needs a small mapping outside: which sheet is which register, and which column is which field. The program proposes the mapping from headers and sample values; you review and confirm it.

Layout of the page

One block per sheet. The heading shows the file, the sheet name and a selector for the register (baptism, marriage, death). If the program guessed the register wrong, switch it here; the field list is then proposed anew for the new register. Below it the table:

ColumnMeaning
Col.The column letter of your table. A range such as S-BF means these columns together form one field, for example forty godparent columns as paten.
HeaderYour header from the first row.
ExamplesA few cell values from this column. This is the quickest way to see whether the proposal is right.
FieldThe field in famrecon. The list shows every field name with a short explanation. "– do not import –" drops the column.
ProposalHow certain the program is: sicher (header and values fit), wahrscheinlich (the header fits), unsicher (yellow; only a weak similarity, or the values look different from what is expected, such as text in a date column). Empty means not recognised; the column would be dropped.

The balance line at the top counts the levels per sheet. Goal: no "unsicher" and no "not recognised" columns that you actually need.

Reading field names

Fields belong to roles. Every register has main roles: baptism kind (child), vater (father), mutter (mother); marriage braeutigam (groom), braut (bride); death verstorbener (deceased). A role can have sub-roles: the bride her father, her mother and her previous husband (vorehe), the deceased his or her spouse (ehepartner). The field name is the path with underscores:

braut_namesurname of the bride
braut_vater_berufoccupation of the bride's father
verstorbener_ehepartnerspouse of the deceased as a whole cell ("Haag, Catharina")
kind_vornamegiven name of the baptised child
vaterfather as a whole cell: name, given name, markers and occupation are split when building

Without a role come the fields of the entry itself: tauf_datum (baptism date), trauung_datum (marriage date), sterbe_datum (death date), begraebnis_datum (burial date), places, paten (godparents), zeugen (witnesses), todesursache (cause of death), unehelich (illegitimate), plus the citation (kb register book, seite page, lfd_nr number, zitat citation) and bemerkung (remark). Fields ending in _rv are back references: a death date the author already wrote into the baptism row. famrecon uses them for linking.

Two suffixes exist everywhere: _kb for the literal register spelling next to a normalised column ("Hanß" next to "Johann"); it is written to the GEDCOM as an additional name form. _praefix for a date qualifier such as "about", "before", "calculated" (GEDCOM ABT, BEF, CAL).

Ranks: what is mandatory

Every field has a rank. Mandatory: without it the entry cannot be used. Per register these are: baptism a given name of the child, a birth or baptism date and at least one parent; marriage a marriage date, groom and bride; death the deceased and a death or burial date. Linking: helps to connect persons across registers (given names, age, origin, parents, spouse, back references). Supplementary: carried along and written out, but decides nothing (godparents, witnesses, minister, remarks).

Treated as "not given"

The input field at the bottom lists placeholders that mean "empty" in your cells: n/a, —, ?, [ ]. The program proposes what it found in the cells. Such values are not read as a name or date but are kept as raw text.

Confirming

Confirm mapping and build saves and reads in immediately. save only saves without reading. The mapping then lies in the project folder as a readable text file zuordnung.toml; it can be copied and reused for another project with the same table layout (see FAQ).

Whatever is set to "do not import" or was not recognised will be missing from the GEDCOM later. Check above all the columns with names, dates and parents.

Building: reading and normal form

When building, famrecon reads every row according to the mapping and brings the values into a normal form it can compute with. The raw value of every cell is kept alongside and appears in the person list and in the review list.

Splitting person cells

A cell such as "Haag, Nicolaus, weyl., gewesener adelicher Kutscher" becomes surname Haag, given name Nicolaus, death marker, occupation gewesener adelicher Kutscher. Recognised markers (German register conventions):

(W), Witwewidowed
(in), ending -infemale (Hagin = Hag)
geb. X, geborene Xbirth name X; the name given becomes the married name
N., NN., NNname unknown
?, (?), (??)uncertain reading
weyl., weil., sel., selig, +, †already deceased at the time of the mention
"Rosenfeld von"becomes "von Rosenfeld" (nobility particle moved to the front)
"Mädchen - totgeboren", "anonymus"stillbirth; the sex from Mädchen (girl), Knabe (boy), Söhnlein, Töchterlein

Age and dates

Age in six notations ("59 J 10 M 4 T", "3 J., 7 M., 14 T", "24 Wochen", "1 Monat", "½ Jahr", "0") is converted to days; from it a calculated birth date with the qualifier CAL results, which is compared with the baptism when linking. Dates with month but no day, or year only, stay as precise as they are.

Phonetic keys

Surnames get a phonetic key (Cologne phonetics) so that Haag and Hag, Kriehmann and Kriemann find each other. Given names get a unified form: Nicolaus = Nikolaus, Hanß = Johann, Catharina = Katharina. The spelling of the entry is kept and appears in the GEDCOM as an additional name form.

Persons

This list shows every mention of a person in the entries, that is the rows of the normal form, not the merged persons. A baptism row yields up to three mentions, a marriage row up to eight (the couple, their parents, previous spouses).

ColumnMeaning
Reg., YearRegister and year of the entry.
RoleThe path: kind, braut_vater, verstorbener_ehepartner and so on.
Name, Given nameNormalised. A dash means: not mentioned.
Markers† mentioned as deceased, ? uncertain reading, NN name unknown, Totgeburt stillbirth.
BirthBirth year if known or calculated; CAL in front means calculated from the age.

The search looks in surname, given name and the raw text of the cell; the selector limits to one register. At most 500 rows are shown, so narrow down for large sets.

Families

One box per family: number F…, marriage year with ⚭, husband and wife, below them the children by year of birth. Every person appears with surname, given name, birth and death year and their number in square brackets; for women the birth name comes first and the married name in parentheses when both are known.

(Ehe erschlossen) means: there is no marriage entry; the family was inferred from baptisms or burials naming the same parents. This is normal for marriages before the register begins or at another place.

The search finds families in which husband, wife or a child matches the search term. At most 300 families are shown. Sorting follows the marriage year, otherwise the first baptism.

How linking computes

All entries run through chronologically, the three registers mixed, because every entry anchors the later ones: the marriage of 1768 carries the baptism of 1770 and the son's marriage of 1795.

Baptism
Father and mother are looked up as a parent family: the father via surname (phonetic key) and given name, the mother confirms or contradicts. If none exists, a new family is created. The child is always a new person.
Marriage
Groom and bride are looked up via name, given name, age or birth date and the parents named. Named parents become the parent family, a previous spouse a previous marriage. If nobody is found, a new person is created.
Death
The deceased is looked up via name, given name, the birth year calculated from the age, the father named, the spouse and back references. Two vetoes: "single" does not fit a person with a marriage, "married" or "widowed" does not fit one without a matching partner.

Points and levels

Every candidate receives points: same given name 100, partial 70; birth date exact 100, year 50, close 30; matching father 30, matching mother 50, matching spouse 50; a death date from a back reference 200; identical spelling of the surname 20. The threshold is 100 points (death 80). Plausibility windows: fathers 16 to 75 years, mothers 15 to 50, marriage 14 to 80, at most 22 years between first and last child of a family, at most 5 years between calculated and documented birth.

sicher (certain)An anchor beyond the name (date, parents, partner) and no close runner-up.
wahrscheinlich (probable)Points above the threshold, no runner-up nearby.
unsicher (uncertain)Points above the threshold, but a second candidate is less than 30 points behind. Goes to the review list.
neu (new)No candidate above the threshold: a new person.

Every assignment carries a plain-text reason ("given name, birth year, father") that appears in the review list. Two families with the same couple are merged into one.

The mechanics are measured: from a known family tree the three registers are generated, linked, and compared with the original. On the bundled example, precision and recall are above 0.99; the errors are siblings with the same given name. Real registers with spelling variants and gaps are harder, which is what the review list is for.

Review list: decisions by hand

The review list shows the uncertain assignments: mentions where two or more persons fit about equally well. It is ordered by year; cases already decided are at the end.

One case

The heading names the mention: register, year, role and the raw text of the cell, plus its number and level. Below, one card per candidate with surname, given name, birth and death year, the person number, the points and the reason, then all evidence for this person: every entry assigned to them so far, with register, year, role and raw text. The first candidate is the program's current choice.

The buttons

After every click, linking runs again immediately and the list reloads. A green field von Hand (by hand) marks decided cases.

What a decision does

Decisions are attached to the table row (file, sheet, row number, role), not to the person numbers, which are reassigned on every run. That is why they survive every rebuild, including after adding tables. They apply before the computation and pull follow-up decisions along: whoever has been merged once receives matching later entries as well.

How to proceed

  1. First decide the cases with a clear anchor: a piece of evidence names the same father, the same birth year, the same spouse.
  2. Leave doubtful cases open. Open cases still go into the GEDCOM, with the program's choice and a note naming the alternatives.
  3. After a series of decisions, look at the families: did the decisions merge or split families as expected?
  4. also show "wahrscheinlich" adds the next level. Worthwhile for small sets or when you want to check a name specifically.

Writing and checking the GEDCOM

The page writes the GEDCOM file (version 5.5.1, UTF-8) and checks it immediately. At the top you see how many persons, families and lines were written.

What goes where

NameGiven name and surname; birth name as first name, married name as second (TYPE married); different spellings from the entries and register forms as additional names (TYPE aka).
Birth, baptismFrom the baptism entry with date and place; godparents as a note under the baptism.
MarriageFrom the marriage entry with date and place; witnesses and minister as a note.
Death, burialFrom the death entry; cause of death (CAUS) and age (AGE) at death.
OccupationOne occupation per mention with the date of the entry; origin as a note.
SourceEvery event with source (file, sheet) and citation (register book, page, number or quote), so you can trace every statement back to its table row.
NotesRemarks of the entries; for an uncertain assignment a note "famrecon: Zuordnung … unsicher" with the alternatives and their points.

Nothing is discarded: whatever has no GEDCOM field becomes a note on the person or the event.

The check

For every table row, famrecon looks for the record in the GEDCOM that must document it: for a baptism a person with birth or baptism and this citation, for a marriage a family with marriage, for a death a person with death or burial. It also verifies that the names of the main persons appear in the record and that all references between persons and families point to existing records. 0 errors means every row arrived. Errors are listed individually; the typical cause is a mandatory field missing from the mapping.

Afterwards

Download GEDCOM saves the file. Import it into Gramps, Ahnenblatt, webtrees, or upload it to an online family book. Gramps offers a database check under Tools that verifies age windows and references once more. Command line users find a rule catalogue with further plausibility checks under Command line.

Command line

The interface calls the same modules as the command line and decides nothing itself. If you prefer the terminal or want to automate runs, use the command famrecon (after pip install .) or python3 -m famrecon:

spalten file.xlsxshow sheets and headers
zuordnung file.xlsx -o zuordnung.tomlpropose the column mapping
bau zuordnung.toml file.xlsx -o projekt.dbread in according to the mapping
verknuepfen projekt.dbform persons and families
personen, familien, prueflisteshow the result (pruefliste --alle includes "wahrscheinlich")
gedcom projekt.db -o projekt.gedwrite the GEDCOM
pruefe projekt.db projekt.gedcheck; exit code 1 if anything is missing
simuliere tree.ged -o register.xlsx --rauschen 0.3generate the three registers from a GEDCOM (measurement)
messen projekt.dbmeasure the linking against the simulation's identifiers
stand projekt.dbwhat the project file contains
start --port 8765 --daten folder --kein-browserstart the interface

The source tree contains a Makefile with the targets test, bau, gedcom, gramps (Gramps reads and checks the file) and plausibilitaet (a rule catalogue with 64 checks). The environment variable FAMRECON_SPRACHE=en forces English.

Data and safety

  • Everything local. famrecon is a program on your computer that shows a page in the browser. It accepts connections only from your own machine (address 127.0.0.1) and never connects to the internet itself. There is no telemetry, no account, no cloud.
  • Data folder. As a single file in your download folder, famrecon creates the folder daten next to itself. Installed (Debian package, Mac application, Windows under "Program Files") it uses the user's data folder: ~/.local/share/famrecon, ~/Library/Application Support/famrecon or %APPDATA%\famrecon. The start page shows the path.
  • Backup. Copy the project folder, done. It contains your tables, the mapping, the decisions and the GEDCOM. The project file projekt.db is a build product and can be regenerated from tables and mapping at any time; the decisions, however, live only in it. So back up the whole folder.
  • Deleting. "Delete project" removes the folder irrevocably. Your original files elsewhere are not affected.
  • Living persons. famrecon does not distinguish living persons; 20th century registers may contain data of living people. Before publishing the GEDCOM, check the protection periods of your archive and the privacy rules of your target system (Gramps and webtrees can hide living persons).
  • Log. Without a console window, famrecon writes messages and errors to the file famrecon.log in the data folder. It helps with bug reports.

Window, quitting, second start

famrecon opens its own window without an address bar if Chrome, Chromium, Brave or Edge is installed; otherwise the default browser. The program keeps running in the background even when you close the window.

Quit
The button at the top right quits famrecon. All data is saved at that moment; there is nothing unsaved. Afterwards the window can be closed.
Window closed, famrecon still running
Simply start famrecon again: it notices that it is already running and only opens a new window.
Address
Default is http://127.0.0.1:8765/. If another program occupies the port, famrecon takes a free one and opens the window with the right address. The command line lets you set a port.
Several windows
You can open the address in more browser windows, for example review list and families side by side. There is only one data set; all windows show the same state after the next reload.

Frequently asked questions

My column is not recognised or proposed wrongly.

Choose the right field from the list on the mapping page; the proposal is only a proposal. If it helps to make the header in the table more telling ("Given name groom" instead of "GN2"), it will be recognised in the next project. If a field is missing from the catalogue entirely, map the column to bemerkung; its content then goes into the GEDCOM as a note.

Two sheets are both baptisms (two volumes, two parishes).

Assign both to the register baptism. Several sheets or files of the same register are allowed; the citation distinguishes them, and the fields kb or ort can carry the volume or parish.

My dates have only the year.

That is enough. With the year alone, linking becomes a little coarser (birth year instead of date) but remains possible. The GEDCOM then receives only the year.

Special characters are broken (CSV).

famrecon tries UTF-8, Windows-1252 and Latin-1. If the mapping still shows wrong characters in the examples, save the CSV in your spreadsheet program as "CSV UTF-8" or upload the table as xlsx.

Why do persons appear as NN?

The entry gives no name (such as "N." or a mother without a name). famrecon creates a person with an unknown name so the family stays complete. If a later entry names the same partner, the person receives the name.

The same person appears twice.

Two mentions do not share enough anchors (given name spelled differently, no age, no parents), or a veto separated them. Only close calls appear in the review list; clear separations you find via Persons or Families. There is no merge button there, but: if the mention appears in the review list with "also show wahrscheinlich", choose "ist diese Person" there. Otherwise it helps to give the entry a distinguishing field in the table (age, father) and rebuild.

Two different persons were merged.

In the review list choose "eigene Person (keiner davon)" for the case in question. If the case is not in the review list because the program was certain, try "also show wahrscheinlich". Same given names among siblings (after a child died young the name was often given again) are the most frequent cause; a death back reference in the baptism row resolves them.

Why does a family have no marriage?

It was inferred from baptisms or burials ("Ehe erschlossen"). The marriage took place before the register begins or elsewhere, or is in a table not yet loaded.

How large may a data set be?

Tens of thousands of entries run in seconds to a few minutes. The views are limited to 500 persons and 300 families per page, so use the search for large sets.

Can I reuse the mapping for a second project?

Yes. Copy the file zuordnung.toml from the project folder into the folder of the new project before building there. It fits when sheet names and columns have the same layout; deviations show on the mapping page.

Do my tables change?

No. famrecon reads copies in the project folder and never writes to your files. The uploaded copies remain unchanged too.

Windows warns about an unknown publisher.

The program file is not signed because a certificate costs money every year. Choose "More info" and "Run anyway". The file comes from the project's release page; make sure you downloaded it from there.

The Mac says the application cannot be opened.

Right-click famrecon.app, "Open", then "Open" again in the dialog. This is only needed on the first start. Alternatively in the terminal: xattr -d com.apple.quarantine famrecon.app.

How do I switch to German?

famrecon follows the system language. The language can be forced with the environment variable FAMRECON_SPRACHE=de (or en) before starting.

I see an error page with a lot of text (traceback).

A bug in the program. The last line names the cause, often an unexpected cell. Please report the text together with a description of what you did; the file famrecon.log in the data folder contains it as well. Your data is not affected; after reloading the page you can continue.
